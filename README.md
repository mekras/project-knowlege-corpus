# Коллекция навыков для корпуса знаний проекта

Коллекция навыков ИИ для создания, сопровождения и применения корпуса знаний
проекта.

Корпус знаний проекта — набор первичных данных и производных материалов, на
которые агент и человек могут опираться при анализе, проектировании,
документировании и проверке решений. Первичные данные входят в корпус знаний и
должны храниться отдельно от нормализованных представлений, извлечённых
утверждений, аналитических выводов и производной документации.

## Установка и обновление

Основной способ использования — установка коллекции через `APM`
([Agent Package Manager](https://github.com/microsoft/apm)).

Установка:

```bash
apm install github.com/mekras/project-knowlege-corpus#^0.3.1
```

Обновление:

```bash
apm update
```

## Использование

### Настройка целевого проекта

Чтобы агенты в целевом проекте использовали корпус знаний при разработке,
настройте проект через навык
[kc-setup](.apm/skills/kc-setup/README.md).

Если корпуса ещё нет, навык спросит имя папки и предложит `knowledge` как
вариант по умолчанию. Если корпус уже есть, навык проверит его через
`kc-validation` и обновит или исправит структуру перед записью правил в
`AGENTS.md`.

### Источники

Источники — места, откуда корпус знаний получает новые или обновлённые сведения.
Это могут быть сайты, папки, видеозаписи, серверы MCP и вообще всё, откуда ваши
агенты могут извлекать данные.

Для добавления источников применяется навык
[kc-sources-add](.apm/skills/kc-sources-add/README.md). Пример добавления источника:

```text
Добавь в корпус знаний источник: https://example.com/foo/bar.html
```

Навык проверит, новый ли это источник, определит где его учитывать, как получать
данные, какие есть ограничения и нужна ли нормализация.

### Конвейер обработки данных

Конвейер обработки данных — сердце корпуса знаний, он обеспечивает движение
данных от их источника до внесения изменений в файлы проекта.

Конвейер состоит из этапов:

- извлечение первичных данных;
- нормализация первичных данных;
- извлечение утверждений;
- анализ влияния;
- внесение изменений в файлы проекта.

Запустить конвейер можно запросом:

```text
Запусти конвейер корпуса знаний.
```

Движение по конвейеру координирует навык
[kc-pipeline](.apm/skills/kc-pipeline/README.md). Он выбирает
следующий этап и подключает подходящие навыки для обработки данных.

#### Извлечение первичных данных

Этот этап нужен только для внешних по отношению к проекту источников: сайтов,
внешних папок, серверов MCP и т. п. Для источников, которые хранятся в самом
проекте, этот этап не применяется.

На этом этапе каждый источник проверяется на наличие обновлений с помощью
настроенных для этого источника адаптера или команды. При наличии обновлений из
источника извлекаются и сохраняются локально _первичные данные_ — данные в
форме, максимально приближенной к их форме в источнике.

Первичные данные — локальная проектная копия данных из источника. Это позволяет
при необходимости обращаться к первичным данным без необходимости каждый раз
извлекать данные из источника.

В зависимости от характера, первичные данные могут добавляться и храниться в VCS
или храниться только на машине разработчика. Это может быть обусловлено их
размером (например, нет смысла хранить в VCS большие видеофайлы), лицензией на
их использование или другими факторами.

#### Стратегии хранения источников

Не каждый источник нужно или можно целиком копировать в корпус знаний. Для
больших баз знаний, дорогих обходов, источников с ограниченной лицензией,
закрытых систем и часто меняющихся внешних ресурсов проект может выбрать
особую стратегию хранения.

Поддерживаемые стратегии:

- `full_copy` — в корпусе хранится полный проверяемый слой первичных данных;
- `local_only` — сырьё хранится только локально, а в Git попадают разрешённые
  метаданные и производные артефакты;
- `index_only` — в Git хранится только индекс единиц источника: где искать
  сведения, как получить единицу, какая у неё тема, статус доступа и
  ограничения;
- `external_reference` — корпус хранит только ссылку на внешний источник и
  условия обращения к нему.

Индексный режим не заменяет нормализацию и извлечение утверждений. Он означает,
что при обновлении источника агент поддерживает только индекс, а нормализацию
делает позже и точечно: выбирает релевантные страницы, файлы или другие единицы,
получает их по запросу, проверяет ограничения доступа и только затем готовит
нормализованный артефакт и извлекает утверждения.

#### Нормализация первичных данных

Это подготовка рабочего представления первичных данных без подмены исходного
материала пересказом агента.

Для нормализации применяется навык
[kc-normalization](.apm/skills/kc-normalization/README.md). Он
готовит проверяемый артефакт для дальнейшего анализа: очищенный текст,
структурированный экспорт, расшифровку или другое представление, которое можно
сопоставить с первичным материалом.

#### Извлечение утверждений

Утверждения — проверяемые факты, наблюдения и спорные фрагменты, извлечённые из
первичных или нормализованных данных.

[kc-statements](.apm/skills/kc-statements/README.md) применяется для извлечения утверждений. Он отделяет
подтверждаемое источником содержание от интерпретации, назначает устойчивые
идентификаторы и готовит материал для анализа влияния.

#### Анализ влияния

Проверка того, какие утверждения корпуса знаний подтверждают, дополняют или
опровергают сведения в документации, требованиях, сценариях, архитектурных
решениях и других файлах проекта.

Для проверки влияния применяется навык
[kc-impact-audit](.apm/skills/kc-impact-audit/README.md). Он сопоставляет
проверяемые данные корпуса с файлами проекта, классифицирует расхождения и
отделяет безопасные правки от вопросов, где нужно решение человека.

#### Изменения в файлах проекта

Изменения в файлах проекта вносятся только после проверки влияния и только в
той области, где источник, актуальность и безопасность публикации уже
проверены.
