# Файловая структура корпуса

Корпус знаний хранит источники, единицы источников, первичные материалы,
нормализованные артефакты и утверждения так, чтобы от проектного вывода можно
было вернуться к конкретному материалу источника.

Проект может выбрать собственные имена каталогов. Ниже описана переносимая
раскладка, которую дают навыки корпуса как стартовый договор.

## Общая схема

```text
corpus.yml
catalog.yml
data/
  <source>/
    source.yml
    items.yml
    <units>/
      <unit>/
        item.yml
        <artifact>
        statements.yml
.local/
  <private-or-heavy-materials>
```

## Корень корпуса

| Путь | Назначение |
| --- | --- |
| `corpus.yml` | Договор корпуса: версия, корни данных, шаблоны путей, политика доступа, поддерживаемые стадии и проверки. |
| `catalog.yml` | Навигационный список источников: идентификатор, название и путь к каталогу источника. |
| `data/` | Отслеживаемый слой источников и их переносимых артефактов. |
| `.local/` | Локальный слой для тяжёлых, приватных или непубликуемых материалов. |

`catalog.yml` помогает найти источник. Полная карточка лежит рядом с
артефактами источника.

Подробнее о выборе способа хранения см.
[«Как выбирать способ работы с источником»](../20-sources/03-source-decisions.md).

## Каталог источника

```text
data/<source>/
  source.yml
  items.yml
```

`data/<source>/source.yml` описывает источник: название, статус, приоритет,
технический носитель, смысловой вид, доступ, стратегию хранения, способ
получения, политику копирования и ограничения.

Минимальные поля карточки источника:

1. `id`;
2. `slug`;
3. `title`;
4. `status`;
5. `carrier_type`;
6. `source_kind`;
7. `adapter`;
8. `storage_strategy`;
9. `retrieval_mode`;
10. `copy_policy`;
11. `access.default`;
12. `reliability`;
13. `refresh_policy`.

`data/<source>/items.yml` хранит индекс единиц источника: страниц, файлов,
сообщений, записей, глав, выпусков или других фрагментов, с которыми корпус
работает отдельно.

## Единица источника

```text
data/<source>/<units>/<unit>/
  item.yml
  normalized.md
  statements.yml
```

`item.yml` описывает конкретную единицу источника: локатор, статус доступа,
стадию обработки, ограничения и ссылки на артефакты рядом с этой единицей.

Артефакты единицы зависят от носителя и способа обработки:

| Артефакт | Когда появляется |
| --- | --- |
| исходный файл или снимок | материал можно хранить в корпусе; |
| расшифровка | источник содержит аудио, видео или речь; |
| результат OCR | источник содержит скан или изображение текста; |
| `normalized.md` или другой нормализованный файл | материал приведён к виду для чтения, поиска и извлечения утверждений; |
| `statements.yml` | из материала извлечены проверяемые утверждения. |

`statements.yml` хранится рядом с материалом, из которого извлечены
утверждения. Так проще проверить связь: источник → единица источника →
артефакт → утверждение.

## Индексы и ссылки

Индексы дают навигацию по корпусу. Материалы источников хранятся в карточках,
артефактах и локальном слое.

В индексах фиксируются:

1. стабильные идентификаторы;
2. названия или краткие темы;
3. локаторы;
4. статус доступа;
5. стадия обработки;
6. ограничения;
7. путь к папке единицы, если рядом есть артефакты.

Пути к переносимым артефактам записываются относительно корня репозитория.
Абсолютные локальные пути, токены, сессии, пароли и закрытые ссылки не попадают
в отслеживаемые файлы.

## Локальный слой

`.local/` используется для материалов, которые нужны в работе и остаются вне
Git: полные книги без права публикации, тяжёлые медиа, временные загрузки,
рабочие файлы извлечения, приватные снимки и закрытые данные.

В отслеживаемом слое остаются переносимые сведения:

1. карточка источника;
2. хэш или другой проверочный признак;
3. размер, формат и другие метаданные;
4. ограничения доступа и публикации;
5. статус извлечения;
6. разрешённые производные артефакты.

## Проверки структуры

Минимальная проверка структуры подтверждает:

1. `corpus.yml`, `catalog.yml`, `source.yml` и `items.yml` существуют;
2. обязательные поля заполнены;
3. идентификаторы уникальны;
4. `catalog.yml` указывает на существующие каталоги источников;
5. ссылки на артефакты ведут к существующим файлам;
6. переносимые пути записаны относительно репозитория;
7. отслеживаемый слой свободен от чувствительных локальных материалов;
8. утверждения можно проследить к конкретному артефакту источника.

В навыке `kc-inventory` есть переносимый пример валидатора:
`.apm/skills/kc-inventory/scripts/validate-corpus-layout.py`.
