# Типы носителя источника

Тип носителя показывает техническую форму первичного материала: как его
получать, раскладывать на единицы, хранить и нормализовать. В карточке
источника это поле называется `carrier_type`; его значения берутся из
`.apm/skills/kc-inventory/assets/source-carrier-types.yml`.

За интерпретацию источника отвечает отдельное поле `source_kind` из
`.apm/skills/kc-inventory/assets/source-kinds.yml`.

Подробнее о смысловой роли материала см.
[«Смысловые виды источников»](02-source-kinds.md).

## Как выбирать носитель

Выбирайте носитель по первичной технической форме материала:

- если материал оформлен для чтения человеком, используйте `document`;
- если основная форма — записи, структурированные для машинной обработки,
  используйте
  `data_export`;
- если перед чтением нужен OCR, расшифровка или визуальное описание,
  используйте `media`;
- если материал доступен как отдельная опубликованная страница, используйте
  `web_page`;
- если источник состоит из множества связанных страниц, используйте `website`;
- если источник — хранилище кода, документов, настроек и истории изменений,
  используйте `repository`;
- если первичный материал — текстовая фиксация речи, используйте `transcript`;
- если материал остаётся во внешнем сервисе или закрытом контуре, используйте
  `external_system`.

Локальный файл, закрытое хранилище и внешний доступ описываются через `locator`,
`storage_strategy`, `retrieval_mode`, `copy_policy` и `access`.

## Примеры сочетаний

Одна и та же смысловая роль может иметь разные носители:

| Источник | `carrier_type` | `source_kind` |
| --- | --- | --- |
| Книга в PDF | `document` | `book` |
| Скан книги | `media` | `book` |
| Статья на сайте | `web_page` | `article` |
| Раздел базы знаний | `website` | `knowledge_base` |
| CSV из CRM | `data_export` | `dataset` или `operational_record` |
| Репозиторий Git | `repository` | `source_code` |
| Тема форума | `external_system` или `website` | `discussion` |

Если источник совмещает несколько технических форм, в `carrier_type`
фиксируется основной носитель, а дополнительные формы записываются в
`processing_notes`.

## Что выбирать дальше

После выбора `carrier_type` становится понятно:

1. какая единица работы нужна: страница, файл, запись, фрагмент, раздел,
   сообщение, кадр или сегмент;
2. какой входной материал нужен для нормализации;
3. какие технические риски есть у хранения и повторной проверки;
4. нужен ли индекс единиц источника;
5. какие дополнительные поля нужно заполнить в карточке источника.

После этого отдельно выбираются `source_kind`, стратегия хранения и способ
получения материала.

Подробнее см. [«Смысловые виды источников»](02-source-kinds.md)
и [«Как выбирать способ работы с источником»](03-source-decisions.md).
