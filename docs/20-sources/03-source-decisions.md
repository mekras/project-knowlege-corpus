# Как выбирать способ работы с источником

После выбора `carrier_type` и `source_kind` в карточке источника фиксируется
способ работы с материалом. Он отвечает на три вопроса:

1. что хранится в корпусе;
2. как материал получается для задачи;
3. какие копии и фрагменты можно переносить в Git и проектные файлы.

Эти решения записываются в полях `storage_strategy`, `retrieval_mode` и
`copy_policy`.

## Что хранится в корпусе

`storage_strategy` показывает, где находится первичный материал или маршрут к
нему.

| Значение | Как работает |
| --- | --- |
| `full_copy` | Корпус хранит полную копию материала. |
| `local_only` | Полный материал есть только в локальном или закрытом слое; в Git остаются метаданные, хэш, ограничения и разрешённые производные артефакты. |
| `index_only` | Корпус хранит индекс единиц источника и правила точечного получения. |
| `external_reference` | Корпус хранит внешний локатор, условия доступа и правило обращения к первоисточнику. |

Полная копия подходит для материалов, которые можно хранить и публиковать вместе
с корпусом. `local_only`, `index_only` и `external_reference` используются,
когда полный материал нельзя, не нужно или слишком дорого переносить в корпус.

## Как материал получается

`retrieval_mode` показывает, как корпус получает материал для конкретной задачи.

| Значение | Как работает |
| --- | --- |
| `synced` | Материал синхронизируется заранее по заданному правилу или команде проекта. |
| `on_demand` | Материал получается точечно, когда он нужен для задачи. |
| `external_reference` | Агент обращается к первоисточнику по сохранённому маршруту. |
| `blocked` | Материал пока нельзя получить: нет доступа, неясны условия или нужно решение владельца проекта. |

Индекс или внешняя ссылка показывают маршрут к источнику, но не заменяют
полученный материал. Для утверждений, анализа влияния и проектных правок нужен
полученный фрагмент или нормализованный артефакт.

## Что можно копировать

`copy_policy` показывает, какой объём материала можно хранить и переносить.

| Значение | Как работает |
| --- | --- |
| `full_copy_allowed` | Полную копию можно хранить в корпусе. |
| `fragments_only` | Можно хранить только допустимые фрагменты. |
| `metadata_only` | В Git остаются только метаданные, статус, хэш, ограничения и маршрут доступа. |
| `no_bulk_copy` | Массовое копирование запрещено; допускается точечная проверка по правилам источника. |
| `local_only` | Полный материал остаётся вне Git в локальном или закрытом слое. |

`allowed_use` описывает разрешённый способ применения материала, а
`requires_access_check` показывает, что перед смысловой обработкой нужно
проверить доступ и условия использования.

## Как эти решения связаны

Один источник может сочетать разные решения:

| Ситуация | `storage_strategy` | `retrieval_mode` | `copy_policy` |
| --- | --- | --- | --- |
| Открытый регламент, который можно публиковать | `full_copy` | `synced` | `full_copy_allowed` |
| Локальная книга без права публикации полного текста | `local_only` | `on_demand` | `local_only` |
| Большая база знаний с выборочной обработкой страниц | `index_only` | `on_demand` | `fragments_only` |
| Закрытая внешняя система проекта | `external_reference` | `external_reference` | `no_bulk_copy` |
| Источник с неясными условиями доступа | `external_reference` | `blocked` | `metadata_only` |

Если данных не хватает, источник остаётся учтённым, но не становится основанием
для утверждений, анализа влияния или проектных правок.
