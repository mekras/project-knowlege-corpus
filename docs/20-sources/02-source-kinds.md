# Смысловые виды источников

Смысловой вид источника показывает, как интерпретировать материал: как правило,
требование, обсуждение, справочник, книгу, исходный код, журнал изменений или
другой вид основания. В карточке источника это поле называется `source_kind`;
его значения берутся из `.apm/skills/kc-inventory/assets/source-kinds.yml`.

`source_kind` выбирается отдельно от `carrier_type`. Один и тот же носитель
может быть разными смысловыми видами: веб-страница может быть статьёй,
регламентом, справочником, журналом изменений или обсуждением.

Подробнее о технической форме материала см.
[«Типы носителя источника»](01-source-types.md).

## Как выбирать смысловой вид

Выбирайте вид по роли материала в работе корпуса:

| Если материал нужен для… | Используйте `source_kind` |
| --- | --- |
| обязательных правил, запретов, процедур и соответствия | `normative` |
| терминов, определений, классификаций и справочных параметров | `reference` |
| статей, карточек и страниц базы знаний | `knowledge_base` |
| поведения продукта, ограничений, критериев приёмки и бизнес-правил | `requirement` |
| уже принятых проектных, архитектурных или организационных решений | `decision_record` |
| мнений, вопросов, предложений и рабочего контекста | `discussion` |
| событий, заявок, инцидентов, операций и журналов | `operational_record` |
| структурированных записей, таблиц, выгрузок и выборок | `dataset` |
| исследований, аналитики, методик и экспертных выводов | `research` |
| авторских публикаций, обзоров и заметок | `article` |
| книг, учебников, руководств и длинных изданий | `book` |
| курсов, лекций, уроков и методических материалов | `training_material` |
| кода, тестов, настроек и исполняемых артефактов | `source_code` |
| записей изменений по версиям или датам | `changelog` |
| фото, видео, аудио, сканов и других медиа как свидетельства | `media_evidence` |
| материала, который пока не укладывается в классификатор | `other` |

## Что меняет смысловой вид

Смысловой вид задаёт правила работы с утверждениями:

1. какую роль играет материал в проектных выводах;
2. какой вес можно придавать утверждениям из источника;
3. что нужно отделять при извлечении: норму, факт, мнение, пример, решение,
   требование, методику или вывод автора;
4. какие ограничения нужно проверить перед переносом сведений в проектные
   файлы.

Например, обсуждение помогает найти контекст и сигналы для проверки, но само по
себе не становится утверждённым решением. Запись решения, нормативный документ,
требование или исходный код дают более сильное основание, но только в своей
области применения и с привязкой к версии, дате или конкретному фрагменту.

## Несколько ролей в одном источнике

Если материал содержит несколько смысловых слоёв, в `source_kind` записывается
основной вид. Дополнительные роли описываются в `processing_notes`.

Примеры:

| Источник | Основной `source_kind` | Дополнительная роль |
| --- | --- | --- |
| Статья с выдержками из стандарта | `article` | нормативные фрагменты |
| Задача с принятым решением | `decision_record` | обсуждение до решения |
| Учебный курс с примерами кода | `training_material` | исходный код в примерах |
| Журнал изменений с миграционными указаниями | `changelog` | требования к обновлению |

## Что выбирать дальше

После выбора `source_kind` становится понятно, как извлекать утверждения и какие
ограничения проверять перед использованием материала. Отдельно выбираются
способ хранения, способ получения и политика копирования.

Подробнее см. [«Как выбирать способ работы с источником»](03-source-decisions.md).
