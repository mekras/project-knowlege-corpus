# kc-setup

Настраивай целевой проект так, чтобы агенты использовали корпус знаний как
проверяемое основание при разработке, анализе, документации и принятии решений.

## Обязательный порядок

1. Определи целевой проект, его корень и файл `AGENTS.md`, который должен
   получить инструкции. Если `AGENTS.md` отсутствует, создай его только после
   проверки локальных правил проекта и явного понимания, что это корневые
   инструкции для агентов.
2. Найди существующий корпус знаний: сначала по `AGENTS.md`, затем по
   проектным манифестам, `corpus.yml`, `catalog.yml` и явно названным путям.
3. Если корпус знаний не найден, спроси у пользователя имя папки для корпуса и
   предложи значение по умолчанию `knowledge`. До ответа не записывай в
   `AGENTS.md` выбранный путь.
4. Если корпус найден, проверь его через `kc-validation`. Если структура
   устарела или повреждена, исправляй её через `kc-inventory` и проектный
   договор корпуса, не меняя смысловые данные без отдельного анализа.
5. Добавь или обнови в `AGENTS.md` отдельный раздел о корпусе знаний. Раздел
   должен называть папку корпуса и обязывать агента использовать корпус при
   разработке проекта.
6. Если в `AGENTS.md` уже есть правила корпуса знаний, обнови их без дублей:
   сохрани локальные ограничения проекта и добавь только недостающие указания.
7. После изменения `AGENTS.md` проверь, что указанная папка корпуса совпадает с
   фактической структурой или явно помечена как выбранная для будущего корпуса.
8. Если в ходе настройки обнаружены новые источники, устаревшие утверждения или
   влияние на проектные файлы, передай следующий шаг в `kc-sources-add`,
   `kc-pipeline`, `kc-validation` или `kc-impact-audit` по ситуации.
9. Если целевой проект применяет профильные навыки, проверь, что их инструкции
   не обходят корпус знаний проекта. Такие навыки должны сначала искать
   релевантные источники, индексы, ограничения доступа и отчёты влияния в
   корпусе целевого проекта, а при неподходящем способе хранения источника
   предлагать изменение стратегии: `index_only`, `external_reference`, точечное
   получение или прямое обращение к первоисточнику.

## Что читать дополнительно

- Формулировку раздела для `AGENTS.md` см. в
  `references/agents-instructions.md`.

## Границы

- Не выбирай имя папки для нового корпуса молча: допустимо предложить
  `knowledge`, но решение должен дать пользователь.
- Не подменяй настройку целевого проекта созданием полного корпуса знаний.
- Не переписывай существующий корпус под переносимый шаблон, если проект уже
  зафиксировал собственный договор структуры.
- Не считай корпус пригодным только по наличию папки: при существующем корпусе
  нужна проверка через `kc-validation`.
- Не добавляй в `AGENTS.md` общие советы без конкретного пути корпуса и
  наблюдаемого правила применения.

## Результат

Сообщай: какой `AGENTS.md` изменён, какая папка корпуса записана, был ли корпус
найден или выбран для создания, чем он проверен, какие структурные исправления
сделаны и какие вопросы остались за пользователем.
